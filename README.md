# خریدیار — دستیار خرید حضوری تهران

دستیار خرید **حضوری** روی دیتاست ترب: پیدا کردن کالا، مقایسه، پیدا کردن فروشنده و پاساژ در محدوده دلخواه، و پیگیری فروشنده تا خرید. فارسی، راست‌به‌چپ و موبایل‌محور.

## چهار گام دستیار

| گام | در محصول |
|---|---|
| **جست‌وجو** | جمله آزاد («دوربین مدار بسته داهوا زیر ۵ میلیون نزدیک جمهوری») → فیلترهای قابل ویرایش (بودجه، محدوده/شعاع، الان باز، گارانتی، ترب‌پی، قسطی، مرتب‌سازی). کارت هر کالا دلیل پیشنهاد را می‌گوید. |
| **مقایسه** | تا ۳ کالا از یک دسته: قیمت ثبت‌شده، تعداد فروشنده، الان باز، تازگی قیمت، فاصله، و جدول مشخصات (اول مشخصات ثبت‌شده برای همه، تفاوت‌ها علامت‌دار). |
| **یافتن فروشنده** | فهرست/نقشه فروشنده‌ها، گروه‌بندی پاساژ («۶ فروشنده در پاساژ علاالدین ۲»)، شعاع، طبقه و واحد، ساعت کاری و «تا ۳۰ دقیقه دیگر می‌بندد». اگر چیزی نبود: **بورس** آن کالا در تهران با نقشه. |
| **پیگیری** | استعلام از فروشنده (گفت‌وگوی شبیه‌سازی‌شده)، ثبت نتیجه، «برام نگه دارید»، و در صورت ناموجود یا تغییر قیمت **جایگزین خودکار**: همین کالا نزدیک‌تر و باز، یا کالای مشابه. صفحه «پیگیری‌ها». |

## شفافیت (قیمت ≠ زمان ثبت ≠ موجودی)

- هر قیمت «قیمت ثبت‌شده» است با سن آن (سبز ≤۷ روز، کهربایی ≤۳۰، قرمز بیشتر با «احتمال تغییر»).
- روی همه کارت‌ها «موجودی تأیید نشده».
- فروشنده‌ای که **این کالا** را ثبت کرده جدا از فروشگاهی است که فقط در **دسته** فعالیت دارد («ممکن است داشته باشند»).
- داده نامعلوم صریح نشان داده می‌شود: «ساعت کاری ثبت نشده»، «شرایط پرداخت نامشخص»، «ثبت نشده» در جدول مشخصات.
- شماره‌های دیتاست نمونه‌اند؛ دکمه‌ها «شماره نمونه» دارند و استعلام به‌صورت **شبیه‌سازی** است و برچسب دارد.

## نظرات (دیتاست نظر ندارد)

به‌جای ساختن نظر جعلی:
- **گزارش واقعی کاربران** از هر فروشگاه: «۴ از ۴ بار موجود بود؛ قیمت ۳ از ۴ بار همان قیمت ترب بود» (۹۰ روز، هر دستگاه یک رأی برای هر کالا؛ پاسخ‌های شبیه‌سازی‌شده هرگز شمرده یا به دیگران نشان داده نمی‌شوند).
- **نشانه‌های داده خود فروشگاه**: معمولاً قیمت‌هایش چقدر قدیمی است، درصد کالاهای گارانتی‌دار، تعداد کالا.
- **چک‌لیست خرید حضوری** هر کالا با منبع هر مورد: «از داده ترب» (کد مدل، فروشنده‌هایی که «طرح/کپی/استوک» ثبت کرده‌اند، گارانتی‌های ثبت‌شده، بازه قیمت)، «راهنمای خرید» (۱۸ دسته بزرگ)، «تولید هوش مصنوعی».

## دیتاست: آنچه اندازه گرفتیم و چطور استفاده شد

| فیلد / یافته | مقدار | تصمیم |
|---|---|---|
| مختصات، آدرس، برچسب محله | ۱۰۰٪ | فاصله، نقشه، مرکز ۳۰ محله (+ نام‌های رایج: جمهوری، لاله‌زار، …) |
| ساعت کاری واقعی | ۶۹٪ (۴٬۴۴۷ فروشگاه) | «الان باز / به‌زودی می‌بندد»؛ شیفت‌های ۰۰:۰۰–۰۰:۰۰ خانه خالی شیفت دوم‌اند، نه ساعت |
| پاساژ / طبقه / واحد از آدرس | ۵۸٪ / ۶۳٪ / ۹۰٪ | گروه‌بندی پاساژ؛ ۴۶۰ ساختمان پس از یکی‌کردن نگارش‌ها («علاالدین ۲»، «علاالدین2»، «مجتمع علاءالدین 2») |
| شرایط پرداخت (ترب‌پی/قسطی) | ۴٪ | فقط نشان و فیلتر، با «نامشخص» برای بقیه |
| دسته فعالیت فروشگاه | ۷۲٪ — هم‌خانواده با دسته کالاها | «ممکن است داشته باشند» و جدول **بورس** (۴٬۲۲۱ کانون برای ۱٬۸۱۳ دسته) |
| قیمت نامعتبر | ۱۵ هزار بدون قیمت، و مقادیری مثل ۱ تومان یا ۱۰¹⁷ | فقط ۱٬۰۰۰ تا ۱۰۰ میلیارد تومان «قیمت ثبت‌شده» حساب می‌شود |
| عنوان «طرح/کپی/استوک» | ۷٬۸۷۳ پیشنهاد | هشدار اصالت در چک‌لیست |
| وبسایت / اینستاگرام | ۱۱۲ فروشگاه واقعی | لینک «صفحه رسمی فروشگاه» |
| مشخصات فنی | آزاد و ناهمگون بین کالاها | مقایسه فقط در یک دسته؛ «ثبت نشده» یعنی نامعلوم |

## معماری

```
Next.js 15 (App Router, RTL)  ──  API routes  ──  PostgreSQL + pg_trgm
   │ صفحات: جست‌وجو، کالا، مقایسه، پیگیری      │ search · simulate · reports · track · alternatives
   │ Leaflet + OSM (قابل تعویض با env)            │
   └── LLM اختیاری (هر API سازگار با OpenAI): فقط وقتی قواعد کافی نیستند
```

- **پارسر قاعده‌محور** (بدون LLM کار می‌کند): بودجه با ارقام فارسی، محله، دسته، برند، شرایط. LLM فقط جمله‌های مبهم را تفسیر می‌کند، با سقف زمانی ۳ ثانیه و کش؛ خروجی‌اش با واژگان خود دیتاست کنترل می‌شود و هیچ‌وقت مقدار قواعد را بازنویسی نمی‌کند.
- **یکسان‌سازی فارسی** واحد برای ورود داده و جست‌وجو (ی/ي، ک/ك، نیم‌فاصله، ارقام).
- **داده کاربر** (`user_reports`) جدا از دیتاست است و قیمت ترب را تغییر نمی‌دهد.
- ۱۱۱ تست واحد (پارسر، ساعت کاری، آدرس، مقایسه، شبیه‌ساز، اعتماد، چک‌لیست، LLM با fetch ساختگی).

## اجرا روی سیستم

```bash
npm install
createdb torob
unzip starcoach-dataset-v16-cap300-csv.zip -d data
DATABASE_URL=postgres://localhost/torob npm run import   # حدود ۱ دقیقه
npm run dev
```

## انتشار روی لیارا

1. در کنسول لیارا یک برنامه **NextJS** با نام `kharidyar` (یا نام دلخواه، در `liara.json`) و یک دیتابیس **PostgreSQL** بسازید.
2. بازیابی داده (فایل `db/dump/torob.dump` حدود ۶۳ مگابایت؛ با `pg_dump -Fc` نسخه ۱۶ ساخته شده):
   ```bash
   pg_restore --no-owner --no-acl -d "$LIARA_DATABASE_URL" db/dump/torob.dump
   ```
3. متغیرهای محیطی برنامه: `DATABASE_URL` (اجباری)، و در صورت تمایل `LLM_BASE_URL`، `LLM_API_KEY`، `LLM_MODEL`، `NEXT_PUBLIC_TILE_URL`.
4. `liara deploy`

## متغیرهای محیطی

| نام | توضیح |
|---|---|
| `DATABASE_URL` | اتصال PostgreSQL |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | اختیاری؛ هر API سازگار با OpenAI |
| `NEXT_PUBLIC_TILE_URL`, `NEXT_PUBLIC_TILE_ATTRIBUTION` | اختیاری؛ کاشی‌های نقشه به‌جای OpenStreetMap |
